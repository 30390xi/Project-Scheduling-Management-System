# 本轮集成契约提案与实施范围

集成人在隔离分支统一落地，四个业务模块仍仅依赖 common；不修改已应用迁移。

1. `AnalysisRequests`：任务提交的可信快照（用户、公司、项目、成员、任务、版本、文本），返回 runId/jobId；D 鉴权并创建分析运行与可靠作业，与 B 提交事务一致。
2. `SkillDirectory`：C 提供公司的有效技能 code，D 用于输出校验。
3. `TaskPlanningPort`：B 按已认证用户展开根任务/依赖，返回版本、业务状态、有效工时、约束、项目候选成员和技能需求；提供计划提交状态更新、变更闭包读取。C 不访问 B 的 Repository。
4. `AllocationLifecycle`：B 在开工/完成/取消事务中调用 C 校验并标记当天开始，保留历史/当天已开始占用，释放未来可移动占用。先锁公司 guard，再任务、明细、容量桶。
5. `PlanningWork`：C 持久化模拟请求，D 的可靠作业适配器调用生成；jobId 与 planId 独立。模拟不占用容量，确认时重读版本/guard/全部硬约束并原子应用净变化。
6. `AnalysisTaskPort`：B 验证任务访问与确认权限、任务版本，先创建完整任务树和依赖，再推进 READY；D 将人工确认、审计、模拟请求一并提交。支持已提交任务在补充需求后按新版本重新分析。
7. 排期入口、方案查询/提交、成员排期/冲突、锁定由 C 提供；所有任务内容可见性均经 B/CompanyAccess 校验。默认只使用项目成员，不擅自扩大资源范围。

审批仍是明确人工动作，模型不直接写容量或确认自己的假设。新增迁移由完整应用测试验证，已有模块测试采用相应测试替身。
