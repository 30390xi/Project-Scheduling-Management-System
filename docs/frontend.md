# 前端管理系统

更新时间：2026-10-07。根据新增需求交付中文 Web 管理界面，产品名为「序程」。前端采用 Vue 3、TypeScript、Vue Router、Vite，图标采用 Lucide；后端继续使用 Java 21 + Spring Boot 3。

## 启动与访问

先启动后端，再启动前端；使用两个终端：

```bash
./scripts/dev.sh
```

```bash
./scripts/frontend.sh
```

需要 Node.js 22.12+（本机使用 22.22.1）。前端脚本首次自动 `npm ci`，随后在 `http://localhost:5173` 启动。通过 `BACKEND_URL` 可修改 Vite 代理目标，默认 `http://127.0.0.1:8080`。不要给前端配置模型 Key。

账号使用本地 `.env` 的 BOOTSTRAP_USERNAME / BOOTSTRAP_PASSWORD。新成员获得临时密码后，界面强制要求先修改密码。浏览器会话有效时刷新或新开标签页可以恢复身份；退出会销毁后端会话。

容器方式：

```bash
docker compose --profile app up --build -d
```

web 容器默认绑定 `127.0.0.1:5173`，Nginx 提供静态文件并把 `/api` 转发到 app:8080。Compose app 使用本地 dev profile；正式部署需配置 HTTPS、独立账号密码、关闭演示初始化，并保留安全 Cookie。不要在本机已运行前后端时同时启动同端口容器。

## 已提供页面

| 页面 | 实际行为 |
| --- | --- |
| 登录 | 账号登录、错误提示、CSRF、会话恢复、首次/重置后改密、退出 |
| 工作概览 | 当前项目任务统计、最近任务、创建入口和配置引导；统计基于已加载的最近 100 项，超过时明确标注 |
| 任务中心 | 状态筛选、已加载任务的名称/编号搜索、游标分页、创建/编辑草稿、批量发起排期模拟 |
| 任务详情 | 描述、分钟估算、优先级、截止与开始日期、固定/偏好负责人、技能要求、前置任务、子任务、状态与工时记录 |
| AI 分析 | 手动提交分析、异步轮询、分析版本切换、三点估算、验收标准、拆分与依赖、缺失信息、失败原因及显式假设确认 |
| 成员排期 | 周视图、成员筛选、上一周/下一周、每日容量/占用/余量、任务明细；公司容量可能包含当前无权查看的项目 |
| 排期方案 | 显示成员/日期/分钟片段、约束冲突、方案有效期；二次确认后提交；过期和版本冲突保留可见错误 |
| 团队与技能 | 成员创建、一次性临时密码展示、角色、启停、技能目录创建、成员认证技能、每日容量、单日日历例外 |
| 项目设置 | 项目创建/重命名、切换项目、项目成员添加/编辑/移除与资源权限 |

无任务时展示真实空状态，不注入模拟数据。未实现的附件/CSV 导入、甘特拖拽、通知中心、模型密钥管理没有放置可点击的占位按钮。排期冲突显示在具体方案内，当前没有跨方案的持久化冲突列表接口。

## 使用顺序

1. 管理员在「团队与技能」新增技能、创建成员，设置技能认证与容量。
2. 在「项目设置」把成员加入项目。
3. 在「任务中心」创建草稿。人工预估可先填写；提交会发起模型分析。
4. 在详情的「AI 分析建议」检查结果，先补齐缺失信息，明确勾选关键假设后确认建议。
5. 检查自动生成的排期模拟方案，确认成员、日期和容量后提交。也可在任务列表勾选就绪任务发起模拟。
6. 在「成员排期」核对安排，再通过任务详情更新开工、阻塞、验收与工时。

前端状态按钮仅作操作引导；后端权限、容量、技能、截止、依赖和版本校验仍是最终依据。项目负责人和公司经理权限不同：公司经理并不自动获得项目负责人权限。

## 实现与安全边界

- `frontend/src/api.ts` 封装同源请求。Cookie 由浏览器管理，每次写操作获取 CSRF token；携带公司选择、If-Match 和适用的幂等键。不会因错误自动重试写请求。
- Vite / Nginx 做同源 `/api` 转发，不改变后端鉴权与 CSRF 规则。
- `GET /api/v1/me` 只返回当前登录者 userId，用于恢复界面身份；权限不依赖浏览器保存的数据。
- 模型 Key 不进入 Vite 环境、浏览器包或页面；页面从后端读取经过验证的分析结果。Vue 文本插值处理任务和模型正文，不使用 v-html。
- 模态框使用原生 dialog，支持焦点约束、Esc 与关闭按钮；提交期间禁用重复操作。小屏采用抽屉导航，宽排期表在区域内横向滚动。
- hash 路由可直接打开任务与方案链接。方案 ID / jobId 保留在 URL；后台没有方案历史列表接口，当前提供按 ID 打开功能。
- 建议确认与方案提交是两个显式用户动作；不自动勾选假设、不自动确认模型结果、不自动提交模拟方案。

## 构建和验证

```bash
npm --prefix frontend ci
npm --prefix frontend run build
npm --prefix frontend run test
# 需要前后端都已运行、本地 .env 内有测试环境登录账号：
cd frontend
npx playwright install chromium
npm run test:e2e
```

浏览器验收包含真实后端 CRUD、会话、成员认证与容量、首次改密和小屏布局；AI 人工确认门槛、过期方案和容量冲突用独立网络替身测试，不消耗模型额度。替身只存在于 tests/e2e，没有生产 mock 模式。真实后端验收会创建带「前端联调验收」标签的项目、合成技能及 ui_check_ 测试成员；草稿会删除，完成的测试账号会停用。只能在可写开发/测试环境运行，不要指向生产。

自动化不保存密码截图或请求 trace。依赖、构建产物、浏览器测试输出及 `.runtime` 均被 Git 忽略。更完整的验证记录见 `docs/reviews/frontend-verification-2026-10-07.md`。
